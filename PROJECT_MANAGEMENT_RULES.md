# PROJECT MANAGEMENT RULES

These rules are MANDATORY for any AI or developer working on the Thomas project.

## 1. 🛑 DO NOT GUESS — VERIFY FIRST

- **Never assume code or files are missing.**
- **Always check the filesystem** (`Get-ChildItem` / `ls`) before proposing to build something from scratch.
- **Check `Inbox` and `Inbox/_Ready_To_Integrate`** for existing ZIP files or feature packs. The user often dumps code there.
- **Check `thomas/core`, `thomas/tools`, and `thomas/server`** for existing modules.

## 2. 🔍 CONFIRM SOURCE OF TRUTH

- **Master Feature List:** `docs/FEATURE_MASTER_LIST.md`
  - This file tracks the status of ALL features (Done vs Inbox vs Missing).
  - Update this file when you find new code or finish a feature.
- **Build Queue:** `FOR_CHATGPT_BUILDS.txt`
  - This file contains **only** the features that are truly missing and need to be generated by an LLM.
  - If you find a feature in the Inbox, **remove it** from this text file.

## 3. 📂 INBOX PROTOCOL

- If you find a ZIP file in `Inbox/` or `Inbox/_Ready_To_Integrate/`:
  - It is considered **"Received / Implemented"**.
  - **Do not rebuild it.**
  - Your job is to **Integrate** it (unzip, merge, wire up).

## 4. 📝 NO DUPLICATE WORK

- Before writing a new `tool`, check `thomas/tools/`.
- Before writing a new `core module`, check `thomas/core/`.
- If a feature seems identical to an existing file, **read the existing file first**.
- If the existing file is a placeholder or broken, **then** you can fix/replace it.

## 5. 🚀 KEEP A CLEAN HOUSE & UPDATE CHANGELOG

- **CHANGELOG.md IS MANDATORY.**
- Every time you add a feature, fix a bug, or integrate a ZIP:
  - **Add a new entry to `CHANGELOG.md`.**
  - **Bump the version** in `pyproject.toml` and `thomas/__init__.py`.
- When moving files (e.g. from Inbox to src), verify they land in the correct `thomas/` subdirectories.

## 6. 🗣️ COMMUNICATION

- If you find conflicting sources (e.g. a ZIP says "v3" but the code says "v2"), **ask the user** which one to trust.
- Do not silently overwrite complex features without confirmation.

---
**NOTE:** `README.md` is for project overview and nuanced documentation. **THIS FILE (`PROJECT_MANAGEMENT_RULES.md`) is the strict rulebook.** If you break these rules, you break the project.
