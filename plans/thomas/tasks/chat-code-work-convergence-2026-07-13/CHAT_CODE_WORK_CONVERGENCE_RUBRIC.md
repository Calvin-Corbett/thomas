- Chat is the default full Thomas conversation: direct answers, inline tools and organic delegation.
- Code adapts the real Forge Code system into a Claude Code/Codex-quality surface with its own history and transparent execution.

## 3. Product laws

1. One Thomas; modes alter workspace contract, not identity.
2. Scope is server-authoritative; localStorage is presentation only.
3. Histories, search, suggestions, memory, skills, artifacts, notifications, exports and deletion are isolated by default.
4. Send to Code, Attach to Work and Continue in Chat produce provenance receipts; history never silently moves.
5. Reuse or formally migrate/retire canonical Chat, Forge, Mission/Autonomy, approvals, audit and artifacts.
6. Every runner, connector, workflow and skill uses one permission/approval path.
7. Claims reconcile against files, tests, processes, state and external effects; text, screenshots, health or exit zero alone prove nothing.
8. Owner data is local, inspectable, exportable, deletable and recoverable; secrets never enter prompt, DOM, logs, exports or evidence.
9. Repository, tool, email, document and web content remain untrusted data and cannot grant access or teach permanence.
10. WorkJob is an owner-facing workspace; autonomy execution, Mission job and code worker remain distinct types.
11. A protected repository path can land only in its S0-assigned CCW-090 batch through the existing human native-auth breakglass with an exact staged-tree audit. Every batch obeys the live 60-file hard cap; every product batch updates the three release files; agent self-approval and unregistered commits are impossible, and only the fully validated final integration tip is a candidate.

## 4. Fail-closed algorithm

- Every leaf independently advances T0 absent; T1 canonical static reachability; T2 deterministic required/forbidden contracts; T3 real server/browser/provider across restart; T4-candidate adversarial isolation, security, recovery, concurrency and honesty using its exact applicable-method cells.
- S0 freezes the dated official-target rows, complete leaf/public-cell/oracle/schema/configuration/verifier universe, public hidden-challenge policy, predecessor-scanner-derived store/producer universe and provider-namespace policy after CCW-010 and before CCW-011; it contains no live provider identity, handle, account hash, sink, grant, label or prefix. Private hidden generators/oracles remain only in the predecessor service package and never enter candidate source, S0 or I0. CCW-091 validates S0 against the finished build, seals result-free implementation I0, then ThomasProofRoot performs exactly one non-repeatable hidden-seed draw and provisions a fresh ordinary-looking provider identity pool from its out-of-band vault; B0 contains only commitments. CCW-092-099 execute public plus broker-delivered hidden cases; CCW-100 seals their results/statuses in C0 and anonymously assigns four fresh graders. The four blind controllers receive only S0+I0+B0 and anonymous out-of-band assignments; the target process receives only ordinary production inputs/accounts/configuration and no proof handle or root. Fresh O alone receives the assignment/seed/provider/sensor reveal after all four deposits, independently rescans raw I0 and archived evidence, and recomputes Efinal with the separately HKLM-pinned adjudicator. No result feeds a grader prerequisite. FAIL, UNPROVEN, STALE or N/A earns no credit; N/A is forbidden.
- A family earns all points only when every atom is T4 PASS; otherwise it earns zero. No averages, partial points, votes or bonus compensation.
- Core is 100. Excellence 10 unlocks only after core 100, all methods green and zero critical failures.
- C2, C5, C8, C9, C10, C11, C12 and C13 are critical. Every non-PASS atom there is a critical failure, caps the score below 60 and blocks release.
- core_raw = sum of family points whose every leaf atom is T4 PASS.
- core_reported = min(core_raw, 59) when any critical atom is not PASS; otherwise core_reported = core_raw.
- excellence_raw = zero unless core_raw = 100 and critical failures = zero; otherwise it is the sum of fully passing excellence families.
- total_score = core_reported + excellence_raw and is reported as total_score/100; the excellence bonus makes the maximum 110/100. PASS requires core_raw = 100, excellence_raw = 10, total_score = 110, G1-G8 all PASS and zero critical failures.
