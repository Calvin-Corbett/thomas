# Thomas Workboard

Last updated: 2026-02-25

This file is the active execution board for agents.
Participation is mandatory for every contributor touching Thomas code, including Codex, Claude, Grok, Thomas, and human operators.
Required operating rules:
- claim scope in `## Agent Claims (Active)` and keep a matching row in `## Active Tasks` before editing
- if work is blocked, add/update an entry in `## Issues / Blockers`
- if work is relinquished, move it to `## Up For Grabs` so another agent can pick it up
- maintain a single task-manager owner in `## Active Tasks`; if unassigned, the first agent touching the board claims it and owns task creation, validation, and ecosystem upgrades

## Execution Protocol (Required)

- Use maximum practical resources for the claimed lane and finish work end-to-end (discovery -> implementation -> verification -> handoff), not partial fragments.
- Every active or parked task must have its own `PLAN.md` under `plans/thomas/tasks/<task_id>/PLAN.md` so future agents can resume without re-discovery.
- Agents must always check in before edits and check out when done:
  - check in: `python scripts/workboard_claim.py --claim --agent "<id>" --scope "<paths>" --task "<summary>"`
  - check out: `python scripts/workboard_claim.py --release --agent "<id>"`
- Task plans are enforced/synced by task manager automation:
  - `python scripts/workboard_task_manager.py --sync-plans --apply`
- Agent alias/session lifecycle is enforced by task manager automation:
  - `python scripts/workboard_task_manager.py --sync-sessions --apply`
- Agent liveness is enforced at a 1-minute idle window:
  - `python scripts/workboard_task_manager.py --sweep-inactive --max-idle-minutes 1 --apply --task-manager-agent "task-manager-agent"`
- When an agent is marked inactive, task manager must either reactivate the task or assign a new one:
  - reactivate: `python scripts/workboard_task_manager.py --reactivate --task-id "<task_id>" --agent "<agent_id>"`
  - reassign: keep task in `## Up For Grabs`, assign to another checked-in agent.
- Agent communication traffic is mandatory for scope changes, blockers, and cross-lane coordination:
  - `python scripts/workboard_message.py --send --from-agent "<agent>" --to-agent "<agent|task-manager-agent>" --summary "<text>" --task-id "<task_id>"`
  - `python scripts/workboard_message.py --ack --msg-id "<msg_id>" --by "<agent>"`
  - `python scripts/workboard_message.py --resolve --msg-id "<msg_id>" --by "<agent>"`
- User orchestration preferences must be captured in summary+verbatim form:
  - `python scripts/workboard_task_manager.py --capture-preference --preference-summary "<summary>" --preference-verbatim "<verbatim>"`

## User Preferences

- Preference source: direct user instruction in chat.
- If the user replies with `ok`, treat it as approval to continue execution without extra confirmation prompts.
- Continue autonomously on the active claimed task after `ok`, unless the next action is destructive or high-risk and needs explicit confirmation.
