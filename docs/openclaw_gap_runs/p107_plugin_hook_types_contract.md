# P107 – Plugin hook types contract

This run adds a Thomas-native *hook types contract* generator for plugins.

## What it does

Thomas plugins implement a set of **hook methods** that are invoked from the agent loop (e.g. agent start/end, tool execution, etc.). This feature provides:

- A canonical **contract** describing the hook surface area:
  - hook name
  - parameters (names, kinds, defaults, and best-effort type annotations)
  - return type (best-effort)
  - async vs sync
- A machine-readable mode (`--json`) for automation and tooling.
- A JSON Schema mode (`--schema`) so external automation can validate the output structure.

The contract is generated by introspecting the plugin base interface (by default `thomas.autonomy.plugin`), or a caller-specified base class.

## CLI

Command (under the plugins command group):

- `p107-plugin-hook-types-contract`

Examples:

```bash
# Human-readable output
thomas plugins p107-plugin-hook-types-contract

# JSON output
thomas plugins p107-plugin-hook-types-contract --json

# JSON Schema output (schema of the JSON contract response)
thomas plugins p107-plugin-hook-types-contract --schema

# Introspect a custom plugin base (useful for testing)
thomas plugins p107-plugin-hook-types-contract --plugin-base mypkg.myplugin:MyPluginBase --json
```

## Config file support

You can provide a JSON or TOML config file:

```json
{
  "plugin_base": "thomas.autonomy.plugin.Plugin",
  "include_inherited": true,
  "include_private": false
}
```

Run:

```bash
thomas plugins p107-plugin-hook-types-contract --config ./hook_contract.json --json
```

CLI flags always override config values.
