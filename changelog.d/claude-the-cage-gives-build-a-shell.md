### Changed

- **In the cage, Build has a shell.** You said: "If the other frontier agents have a cage shell, then he needs a cage shell... If he can't run shell, that's like literally not having hands for AI." Until now a Build run got a shell only at Open guardrails, a dial that asks for your Windows Hello, because that shell ran as you. So a Thomas project's team could not run its own tests, ruff or git ("I did not run pytest myself -- direct shell is unavailable"), and most of what its hand-ins got wrong came from that. In the caged Thomas a shell runs as the cage account: it cannot write Thomas's own code, and a firewall rule blocks every connection it opens except loopback, so its only way onto the internet is the cage proxy's pinned hosts. An editing run there now gets that shell at the default Guarded preset too, on Claude and on Thomas's own agent loop alike; only Fortress, the strict preset, keeps it out. Whether the run is the cage account is read from Windows itself, never from a variable, so your own account never gets a shell this way. The run, and Build's capability report, say exactly what the shell is.
