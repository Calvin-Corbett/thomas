### Changed

- **A change's tests run as an account that cannot write their verdict.** The window's checker (`thomas-checker`) writes the results it posts back, so a change whose own code ran as that account while it was checked could have written its own "passed", or another waiting job's. Now every test process runs as a separate account, `thomas-runner`, which your one elevated setup step (`scripts/cage/enable_window.ps1`) gives read on your code and write only inside a throwaway copy of the change — never the folders where jobs, results or the checker's own state live. The checker refuses to run any other way: with no separate runner account set up, it answers every job "could not check" rather than run a change's tests as itself. The window's second look still stands behind the test.
