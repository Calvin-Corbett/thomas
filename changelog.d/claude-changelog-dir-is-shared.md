### Fixed

- **A P0 sat unclaimable because the directory every agent must write to was treated as one agent's territory.** The commit path requires a changelog fragment, and `changelog.d/` exists so each agent writes its own file -- its README says one fragment per agent per change, so nobody edits anybody else's changelog words. A task whose scope named the bare `changelog.d` directory therefore collided with every agent that had a fragment open, and the task manager refused to reactivate `LIVE-AUDIT-REPAIRS-904` on every retry, naming a different agent each time. That is the same deadlock the workboard itself hit on the same day, one directory over: a path everyone must write cannot also be exclusively owned. `changelog.d` joins `plans/thomas/WORKBOARD.md` in `SHARED_INFRASTRUCTURE`, so it stays legal inside a claim scope -- an agent must still stage its own fragment -- but is never a reason to refuse someone else's claim.

### Changed

- **One rule, one registry.** `workboard_claims.py` and `claim_ownership.py` each declared their own copy of `SHARED_INFRASTRUCTURE`, and the two were equal only by coincidence. The gate refuses a claim; the other module answers which agents hold a path. A path added to one and not the other would deadlock through whichever half was missed, and nothing would report it -- the same one-rule-two-registrations shape that let the workboard inbox gate run advisory in `.pre-commit-config.yaml` while `commit.py` invoked it blocking. `claim_ownership` now re-exports the gate's set rather than restating it, and a test asserts the two are the same object rather than merely equal today.
