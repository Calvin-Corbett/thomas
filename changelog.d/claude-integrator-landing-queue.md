### Added

- **`scripts/crew/brief/land.py`: a first-in, first-out landing queue in front of the unchanged commit tool.** Ten simulated agents landed about as fast as one because every waiting agent kept running the full gate ladder against a branch that kept moving. `land.py` takes the commit tool's own arguments, runs its dry run first so a change that would be refused never takes a place in line, hands out numbered tickets, lets one landing run at a time with a lease, and keeps waiting agents' presence heartbeats fresh so the dead-claim sweep does not reap them. A holder that dies, hangs or goes quiet is skipped and its agent gets a written notice. Every landing carries a `Landing-Ticket` trailer that is checked against dev's history before and after a skip, so a landing that happened is never repeated. `land.py --status` shows the queue and `--verify` reports edited or deleted tickets.
- **The ticket folder is one setting.** `THOMAS_LANDING_QUEUE_DIR`, defaulting to the shared `runtime/coordination/landing_queue`, with the lane logic kept apart from the ticket store so a later stage can move it under the cage's channel folder. Today every agent runs as your account, so the queue is tamper-evident, not tamper-proof; real enforcement needs the commit tool to refuse a landing without a slot, which touches protected files and your sign-in. See `docs/ops/LANDING_QUEUE_DESIGN.md`.
