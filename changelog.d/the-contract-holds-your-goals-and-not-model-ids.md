### Fixed

- **A model id in your request is no longer a file the run has to make.** The acceptance contract read "damo-vilab/text-to-video-ms-1.7b" as a path ending in the extension ".7b" and required it to exist and be non-empty when the work was done; nothing could make it, and the run looped on it. Only versions and model sizes stop being required outputs: a path your request names that is not on disk and does not end in a known extension, whose ending after the last dot is "v" and digits (".v2" in "config/settings.v2") or digits with at most one letter right after a digit (".7b" in that model id, ".1" in "meta-llama/Llama-3.1-8B-Instruct", ".5" in "releases/v2.5", ".0" in "data/file-2.0"). Every other path is an output as before, whatever its extension: "prisma/schema.prisma", "tools/go.mod", "docker/Dockerfile.prod", "man/thomas.1", "lib/libssl.so.3", "dist/site-1.7z", `socket.io`, and every source extension the contract already reads (.vue .svelte .kt .scala .cc among them). A named file that is on disk is read as before. The [0.19.36] 2026-09-07 entry in CHANGELOG.md described this fix as landed; only its test had landed, and it has failed on dev since. (`thomas/core/acceptance_paths.py`, `thomas/core/acceptance_contract.py`, `tests/test_a_model_id_is_not_an_output_file.py`)
- **Your standing goals reach the acceptance contract wherever a separate judge rules.** You asked for goals ("you can make goals"), and the [0.19.36] 2026-09-07 entry in CHANGELOG.md said every standing goal rides into the contract as a judged requirement. The goal book, the goal tools and the contract's place for a goal landed; the one call that reads the goals into the contract did not, so no turn was ever held to a goal, and its test has failed on dev since. `load_learned` now adds every standing goal, and a retired one stays out. Goals ride at the xhigh and max levels, where a separate judge rules on each requirement; a Build runs at xhigh by default. Below xhigh nothing would check a goal, so it stays out of the contract instead of being listed as unchecked under every reply, and a goal alone never turns a turn with nothing to check into one with a contract. A goals file of the wrong shape (`"goals": 5`) is read as holding no goals, as a file that cannot be parsed already was, so `goal.add`, `goal.list` and `goal.done` no longer fail on it and the project's learned checks still load. (`thomas/core/acceptance_learning.py`, `thomas/core/goal_book.py`, `thomas/agent/acceptance_runtime.py`, `tests/test_goals_are_standing_requirements.py`)
