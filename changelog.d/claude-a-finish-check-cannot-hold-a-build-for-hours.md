### Fixed

- **A Build run's finish check can no longer hold the run for hours.** On 2026-10-07 all four Thomas Build runs held at their finish for about 3 hours: each team's `VERIFY:` was a bare `python -m pytest`, the whole suite, and the check's time limit stopped only `cmd.exe`, while the venv's python launcher and the interpreter under it kept the check's output pipes open until the suite was done. The check's command now starts inside a Windows job that is closed when the check ends, and writes its output to temporary files: at the time limit everything it started is stopped and the check reports `timed out after 600s` at once, and anything it left running when it ended is stopped too. A whole-suite pytest still runs, because in a small project it passes in seconds and refusing it would cost the team a whole extra pass. When a pytest check runs out of time, the check now says what to run instead: for a pytest that names no test file, path, node id or `-k`, to name the test files the work changed; for one that does, to narrow it to those tests. (`thomas/core/contained_process.py`, `thomas/core/acceptance_contract.py`, `thomas/core/verify_command_policy.py`, `tests/test_a_finish_check_cannot_hold_a_build_for_hours.py`)
