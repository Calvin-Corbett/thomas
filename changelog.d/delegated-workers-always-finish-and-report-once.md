### Fixed

- Twenty or more background tasks finishing together no longer freeze Thomas. Background workers used to share the server's general thread pool, which has 20 threads on a 16-core machine, and each finishing worker held one of those threads while it waited for its completion notice, which needed a thread from the same pool. Once 20 finished together, their tasks were recorded as done but you were never told, none of them let go of its thread, and anything else that needed that pool waited too. Background workers now run on a pool of their own, 16 at a time unless you set `THOMAS_DELEGATION_MAX_ACTIVE_WORKERS`. The rest wait their turn in order: a waiting task says it is waiting for a free worker, is never failed for the wait, and never starts if it is stopped or ends while it waits.
- A background task now keeps the first ending recorded for it, and you hear that ending once. A worker and its watchdog could both end the same task, and whichever wrote second replaced the first, so you could be told "timed out" about a task that had completed, or hear that it completed after it had been timed out. A later ending is now only noted on the task's record, the chat repeats the ending that was stored, and a late worker no longer writes its result over a task that has already ended.
- Max-effort background tasks start again. Every one failed as it started, because the worker was handed something the Max runner did not accept. A Max task that times out or that you stop now also keeps that reason instead of a generic "cancelled".
- A background task whose worker crashes now ends as failed and tells you so once, naming what went wrong without repeating its raw text. Before, it went on showing as running until a sweep failed it 15 minutes later.
- When Chat tells you a background task has finished, it marks that task as reported on the record it was read from, so the same task is not announced again after a restart, even when two of your projects hold a task with the same id.
