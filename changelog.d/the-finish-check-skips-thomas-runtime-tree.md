### Fixed

- **The check at the end of a run no longer walks Thomas's runtime tree, and a walk that cannot finish holds the run.** To judge a run, the acceptance contract walks the run's folder three times for the source files its checks read. From your checkout that walk went through `runtime/` as well, about 566,000 files, and one walk took 29.4 s. It now skips the top-level `runtime/` of a Thomas checkout (or one that holds the doppelganger), any `.thomas` or `venvs` folder, and the dependency and cache folders it already skipped, in any letter case: the same walk takes about 0.7 s. Every other `runtime` folder is still read, because `thomas/server/web/js/runtime` holds 100 of Thomas's own scripts and a project may keep its own source in one. A walk still going after 60 s stops. A broken file or a page that detects automation among the files it already read still fails its check. A check those files cannot settle counts as not met, the same as a failed check: it holds the run wherever a failed check would, and the run's verification lines show it as FAILED with the reason. The 2026-09-07 changelog already described a fix for this walk and its two tests landed that day, but the code never did, so both tests had failed on dev since.
- **Agent-loop tests run from an empty folder, so the check before your card no longer walks the repo for these tests.** Seven agent-loop test files drove the loop from whatever folder pytest started in. In the repo copy the check before your card runs on, every finish check in those files walked the whole copy, and one test's request to "fix configuration in thomas.toml" read the copy's real `thomas.toml` and searched 600 source files for each of its fields. The 13 agent-loop test files took 83 s from a repo copy and now take 18 s.
