### Added

- **A Build reply is now drawn as blocks, and a new kind of block can be plugged in.** You asked for a way to hot-swap what the feed can show beyond text and a table. Every reply is now a list of blocks, `{type, version, data, fallback_text}`, and `fallback_text` is required: a block with no renderer, one that is switched off, or one whose renderer throws shows its words instead of nothing. A renderer joins through `window.ThomasDisplay.register(type, {render, css})` in `display_kernel.js`, and registering the same type again swaps it with no restart. Two ship first, both in `display_builtins.js`: `markdown`, which wraps the existing renderer so a plain reply draws exactly as before, and `table`, with a line under every row, a stripe on every other row and a heavier line under the header. Build's reply goes through the markdown block; Chat is unchanged.
- **A "Reply display types" row on the Plugins page.** `GET /api/display/types` and `POST /api/display/types/{type}` list and change which block types are switched off, saved in `display_types.json` in the data folder. Off removes the two routes and leaves every type drawn with its own renderer.
