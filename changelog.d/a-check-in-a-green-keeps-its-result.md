### Fixed

- **A test run a Build team starts with check.run in a caged Thomas's green keeps its result while that Thomas writes its own database.** Your test runs fail when your real Thomas data changes under them, and stand down only for a run marked as a green's. The caged shell marked a green's commands and check.run did not, so on 2026-10-13 a team's 162 passing tests were failed for the caged server's `thomas.db-wal`, and two runs were lost. check.run now marks a check as the green's only when it runs as the cage account in a green the server made, judged by where the folder is and the record the server keeps outside it, and it never passes the mark on anywhere else, not even one it inherited. Greens made by the Thomas that runs as you are not covered: their tests run as you over your real data, so the tripwire stays armed there.
