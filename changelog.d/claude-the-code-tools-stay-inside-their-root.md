### Security

- **The code tools no longer read the folder beside the one you pointed them at.** `C:\x\work2` passed as being inside `C:\x\work`, because the check compared the two names letter by letter. `code.search`, `code.find_definition`, `code.find_references` and `code.project_structure` now compare real folders, so naming that folder, or a link leading to it, is refused. The `fs.*` tools and the agent loop use the same comparison, which also stops a separate folder spelled with the Kelvin sign (U+212A) in place of a `k` from passing as yours: Windows keeps the two apart on disk, and Python's own path comparison reads them as one.
- **A search with no path stays inside the folder too.** Leaving the path out used to walk through any junction under the folder and read what was on the other side, and `code.find_definition` and `code.project_structure` did this on every machine. Walks now stop at every junction and symbolic link. `code.project_structure` still shows you the link, marked `(link, not followed)`.
- **A search pattern that starts with a dash is only a pattern.** ripgrep read one as a flag, so `-Lemarker` followed links out of the folder and `--file=<path>` tested the contents of a file outside it. `--pre=<program>` could run a program when the folder's path also parsed as a regular expression, as `C:\work\src` and any Linux or macOS path do.
- **A network path is refused before anything opens it.** `\\host\share\x` went to the filesystem first and was refused afterwards, and on the way Windows could offer your account's credentials to that host. The code tools and the agent loop's check for read tools now refuse another drive or host from the text of the path alone.
- **The code tools can no longer read the runtime protection signing key.** The `fs.*` tools already refused it, but `code.search` read it when it was named outright, when a glob asked for it, or when the Python search walked its folder. A key read this way could be used to forge a switch-off of runtime protection.
- **Thomas can no longer write into a folder that only reads like one you allowed.** `fs.write_file` wrote into that Kelvin sign folder whenever your file-access level allowed the real one, because the write check read the two as one name. It now compares folders the way the disk does, and so do the benchmark lane's two root checks. The list of system folders that are never writable keeps the wider reading on purpose, so it refuses everything it refused before.

### Fixed

- **`code.search` and `code.find_references` answer when the folder does not exist.** With ripgrep installed they raised `NotADirectoryError`; now they say nothing was found, as they already did without ripgrep.
