### Changed

- **The Realtime Human Assistant Layer page can now be turned off and on while Thomas runs.** Its four routes moved out of the server's fixed list into a row called Realtime assistant page, which ships on, so nothing changes until you turn it off. Nothing in Thomas uses this page: no page links to it, so you reach it only by typing its address, and it moved so that you can turn it off. It does not work today, and this does not change that. As it comes a setting of its own keeps it disabled, so Connect shows a warning that it is disabled, and the page keeps trying again about twice a second until you press Connect a second time. That loop is older than this move and is left as it was. With that setting changed it connects, but every message comes back as an error, because it asks `/api/chat` in a shape that route refuses. While the row is off its address shows 404: Not Found. A copy you pressed Connect on and left open says text mode still works, which it does not, and tries again about every eight seconds. Once the row is back on, that copy shows the disabled warning again and goes back to trying about twice a second. Installed with pip inside the Thomas folder, as the install scripts do it, the page is there. In Docker, or installed with pip anywhere else, its address shows 404: Not Found even with the row on. A server started with the row off never loads its code. Turned off on a running server, the routes go at once, anything on the socket is dropped, and the code stays loaded until the next restart. `/api/health` no longer reports on this feature, so turning it off cannot mark Thomas degraded.
