### Fixed

- **A plugin that starts along with Thomas now answers only once it has finished starting.** Its addresses used to be up while its startup work ran, so it could answer with an error, and if that work failed it went on answering. It now reads as loading until it is ready, exactly as one you turn on later does, and one that fails never begins answering. Thomas does not wait for it, so no plugin can hold up the start.
- **Stop now can no longer hang on a plugin, and closing Thomas no longer hangs on what a stop left behind.** A plugin whose code ignored being told to stop could hold the off switch for ever and keep Thomas from closing. Stop now and shutdown each give it 10 seconds, then go on without it and name in the log what they left running. Thomas then closes around that code, so it lets go of its lock and a restart you asked for goes ahead. Turning a plugin off the ordinary way still waits for as long as its work takes, and so does anything else still finishing as Thomas closes, such as a save. That includes work a plugin starts for itself rather than through Thomas: no stop knows about it, so if it ignores being told to stop it can still hold Thomas open.
- **A plugin can no longer take over one of Thomas's addresses with a pattern.** A plugin's address like `/api/things/{id}` used to answer in place of Thomas's own `/api/things/stats`, with no error anywhere. That plugin now fails and names both addresses, the same as one claiming the very address Thomas holds, and the rest carry on.
- **A switch that worked now says so.** If something that keeps its own list of addresses failed to update after a plugin was turned off or on, the press answered with an error even though the plugin had already changed. That failure now goes in the log, and the switch answers as it should.
- **A press that is refused now changes nothing.** A plugin turning itself off from inside its own work is refused, because it would wait for itself. That press still saved it as off first, so it ran on and came back off at the next restart.
- **A plugin whose startup work is cancelled by something else now reads as failed, and says so.** It used to read as loading for ever, with no reason and no way to tell, and Try again now works on it.
