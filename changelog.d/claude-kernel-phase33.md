### Changed

- **Installed plugins are mounted on the kernel instead of rebuilt on every hook.** Phase 3.2 built the host; this puts the one real tenant in it. Each enabled plugin becomes a kernel plugin whose hooks are subscriptions, registered once at server startup and removed exactly when it unmounts — where before, every single hook dispatch re-read `installed_plugins.json` and rebuilt the instances. Hook lookup and the four argument conventions still go through the existing p108 helpers, so a plugin behaves identically to how it did through `run_hook`. The dispatcher stands its legacy per-call scan down while the mount is present, so nothing fires twice, and picks it back up the moment the plugins unmount. Server cleanup disposes the mount, which unwinds every registration the plugins made — teardown is no longer a second implementation that has to be kept in step with setup.

- **A plugin that contributes nothing says so.** `contributing_nothing` — on the supervisor that holds the mounts, and in the plugin systems report — lists plugins that mounted but registered no hook at all. Installed and enabled reads like doing something; for these it is not, and that is now a line you can print rather than a silence you have to notice.

### Fixed

- **The bundled extension packs were never running, and nothing said so.** The spec's phrase was "remount the four existing plugin systems", which implied four runtimes. Reading them says otherwise, and the difference matters: `extensions/` is a catalog, not a runtime. `extension_catalog_runtime` validates that each pack ships a `hooks.py` and never imports it, and no code path in the repository loads pack code at all — no `import_module`, no `spec_from_file`, nothing. So the 533 packs' `before_tool` and `after_tool` have not been discarded; they have never once been called. `agent_plugins_*` and `desktop_plugins_*` are installers that place skills, register MCP servers and build surface URLs, with no hook dispatch to move. `plugin_systems_report()` states what each of the four actually is and its live state, and a test pins the packs as catalog-only so this cannot quietly be misread again. Switching 528 handlers on — each of which stamps a constant into a dict — would have been the wrong repair for a thing whose real problem is that nobody knew it was off.
