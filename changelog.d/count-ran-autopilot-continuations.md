### Fixed
- Autopilot counts self-continuations toward its 12-run limit only with recorded model output or tool activity. Queued requests, refused launches, startup errors, quota-only failures and ambiguous historical receipts do not spend a run; restarted continuations count when their resumed work actually executes.
- Model speech is distinguished from raw process output in the event translators, so a CLI banner or startup diagnostic cannot masquerade as an executed continuation. Model updates beginning with “Not logged in” or “Please run /login” count as execution when they discuss the work rather than reproduce a complete sign-in diagnostic.
- The conversation API and Build conversation show the counted runs since your latest instruction, with each recorded outcome, ending reason, run ID and timestamp. The cap decision and issue records also include each counted run's outcome and reason; ordinary finished-turn receipts retain their existing label.
- Interrupted-run recovery preserves a pending handoff across refused starts even when the original action receipt is missing. Restart launches retain admission checks and guarded-start coordination while recording interrupted endings. Restart-accounting tests use isolated runner probes and immediate retry sleeps.
- Chat-project tests use temporary persistence rather than the process-wide state file. The 600-task heartbeat test offloads its setup writes so those writes do not block its event-loop timing probe.
