### Fixed

- **Your window takes a checker answer only once the checker has finished, and reads it again before it acts.** The checker now writes its answer and then a completion receipt that binds the whole job and the answer; until the receipt is there, the answer is not taken, so a change's own test can no longer get a PASSED read before the real answer arrives. An answer that was already there before the checker ran the job is answered "an answer the checker did not write", never run on and never a pass. A taken answer is read again before a landing, before the check after a landing lets the next change go, and before an approved undo lands; an answer that changed or vanished means the change is checked again. One limit stays: the receipts live in the checker's state folder, which the tests the checker runs can still write until they run under an identity of their own.
