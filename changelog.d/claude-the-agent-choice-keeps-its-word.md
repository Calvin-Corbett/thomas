### Fixed

- **Picking Claude Code in Chat's hand-off to Build works.** The hand-off sent the agent you picked but always sent GPT-5.6 Sol as the model, so every Claude Code pick was refused with "Claude Code cannot run gpt-5.6-sol" (HTTP 400). With a pick, Chat now sends the model on your chip, which the picker has already checked that agent can run. If a hand-off names an agent but no model, it runs that agent's own default (Sonnet for Claude Code). With no pick, a hand-off runs exactly as before.
- **The Agent picker matches the model on your chip from the moment the page loads.** The menu was built before the chip knew its model and never rebuilt, so a GPT model still offered Claude Code, and Build refused the pick. It is now rebuilt whenever the chip's model changes, including the first time. Thomas is no longer offered for a Claude model when there is no Anthropic key; the option says why instead. The picker now sits inside the model chip, so it moves with the chip into the browser bar instead of staying behind in the Chat header. A tab under the bar sends what the bar's picker shows.
- **An Anthropic key you saved in Thomas is one Thomas's loop uses.** The refusal told you to "add ANTHROPIC_API_KEY in Settings", but Thomas's loop read only the server's environment. It now also reads the key saved for the anthropic model in the model menu, in thomas.toml, or in Settings > Anthropic Configuration, and the refusal names the model menu and Settings (not thomas.toml). A saved key reaches the Build run the same way your ChatGPT sign-in does: on the run's one-time start pipe, never in its environment.
- **`ANTHROPIC_BASE_URL` in its usual form works.** It is the Anthropic SDK's setting, which leaves out `/v1`, and Claude Code sessions on this machine set it to `https://api.anthropic.com`. Copied as it was, it made Anthropic answer 404. Thomas now adds the `/v1` its own connection needs.
- **A key no longer silently moves a conversation off Claude Code.** With an Anthropic key present and no agent picked, every existing Claude conversation that had run on Claude Code switched to Thomas's loop billed to the key, and its turns stopped being recorded as Claude Code's. A conversation now stays on the agent that ran its earlier turns until you pick another, and the run's report says so. A new conversation still gets the default, and the picker names that default ("Default (Thomas)") before you send.

### Changed

- **The test that proves the cage shell reads your account from Windows can fail again.** A test-wide stand-in answered "not the cage account" for every test, including the one that checks how the account is read, so a version that trusted the `USERNAME` variable still passed. That test now keeps the real reader, compares it with what Windows' `whoami` reports, and sets the variables to the opposite answer, so trusting them fails whether the suite runs as you or as the cage account.
- **The unused kernel-plugin path for coding agents is gone.** `mount_builtin_agents`, `mounted_registry`, `CodingAgentPlugin` and `CODING_AGENTS` had no caller outside their own test. The docstrings that described it, or named a `/api/code/agents` route that does not exist, now describe what the code does.
