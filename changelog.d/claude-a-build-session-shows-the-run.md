### Fixed

- **Build shows the run, not just a session that exists.** The worker's steps live in `task_bot_runtime` and the Activity panel renders a conversation turn's transcript as forge events, and nothing translated between them, so a session opened to an empty pane for the whole life of a run. The worker's `progress`/`text`/`tool_start`/`tool_output`/`error` events are now recorded as `meta`/`say`/`tool`/`tool_result`/`error` on the bound conversation.
- **It fills in while the run is going, not after it ends.** The new `forge_code_store.upsert_run_transcript` rewrites one turn keyed on the run id, throttled to once a second, so opening a twelve-minute build shows what it is doing rather than nothing until it finishes.
- **Asking for a web page no longer reads as asking to edit Thomas.** `send_task`'s `workspace` field described `project` as "the currently selected project", which is exactly what someone building a page believes they are in, so ordinary requests were routed onto the self-development path and killed with "project file access is not enabled". It now says plainly that `project` means Thomas's own source code and that everything else is `isolated`.
- **That refusal names a way forward.** When a task really would change Thomas itself, the message now says so, says which setting stopped it, and offers to build it as a new project instead — rather than naming an internal control and ending red.
