### Fixed

- **A usage limit pauses Autopilot until it resets, instead of spending its retries.** When your model plan's usage limit is reached (a ChatGPT or Anthropic 429 with a quota code, or a reset more than ten minutes away), Autopilot now waits for the reset time the error gives, or looks again in 30 minutes when it gives none. Waiting never counts toward its 12 self-continuations. The pause is stored with the conversation, so a restart picks it up, and Thomas carries on by himself once the limit resets; if the limit still holds, he pauses again with the new time. The chat and its task card say "Paused: your ChatGPT Pro usage limit is reached. It resets Saturday 26 September at 08:02, and Thomas carries on by himself then.", never "12 self-continuations already tried", and they say so when the next run starts. Stop clears a pause, and a steer ends it early.
- **Your Claude plan's limit pauses Autopilot too.** Build on your Claude plan runs through the Claude Code CLI, which reports its limit as "You've hit your session limit · resets 12:20pm (America/Chicago)" and exits 1. Thomas read that as a crash ("claude exited 1") and would have spent all 12 continuations on it. Thomas now keeps the reset time the CLI sends with the refusal. If there is none, he reads the time the CLI printed; this machine cannot look up that time zone, so he reads it on its own clock and waits an extra hour. The run is recorded as your plan's limit, and Autopilot pauses until the reset, with "Paused: your Claude usage limit is reached." Anthropic's short-lived throttling ("not your usage limit") is still retried as before.
- **A paused build is never lost, and never waits forever.**
  - The server learns its own port when it starts, so after a restart a paused build carries on at its reset. Before this, it waited until you opened Build or Chat.
  - A pause stays listed until the run after it has recorded its end, so a restart, crash or shutdown mid-start cannot lose it. The list is rebuilt from the conversations when the server starts.
  - Each pause belongs to the server that made it, and two servers from one checkout share the list under a lock.
  - Some resets cannot be read: one the error cut off, one already past, or one more than a month away. Thomas treats those as unknown. An unknown reset and a refused start both wait longer each time, up to six hours.
  - After 12 limits in a row, or 6 refused starts, Autopilot stops. The card says so, for example "your ChatGPT usage limit was still reached after 13 tries in a row. Send a message and Thomas carries on". It does not keep saying it will carry on by itself.
  - A limit that follows an earlier error in the same run is recognised too.
