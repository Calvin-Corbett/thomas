### Added

- **`manager.py --monitor` now runs the dead-claim sweep, and `--apply` is deliberate.** The monitor was documented as sweeping inactive agents but its loop did nothing, so a claim left by an agent that died stayed on the board until someone ran the sweep by hand. Each cycle now reports stale claims. `--apply` reclaims only the claims named with `--only AGENT[,AGENT]`; without `--only` it reaps nothing and lists what it would take. A claim younger than 24 hours by its own `claimed_at`, or whose agent has a recent presence heartbeat, is never stale. One claim with no timing evidence is held back alone. A release the presence gate refuses is retried under a reasoned, reported override instead of being counted as a failure, a re-run does not ping or open a second issue, git blame is cached and time-bounded, and a failing cycle is logged with its traceback and counted (the fifth in a row is raised). `--skip-plan-sync` ends the start-up plan check, which exits 1 when any task has no plan file and so would stop the monitor before its first sweep. The liveness check finds a claim by its agent id, not by a line number that shifts when any claim above it changes, and an unreadable or empty board spares the claim.
