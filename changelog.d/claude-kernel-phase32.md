### Added

- **A kernel where a registration knows how to undo itself.** You asked on 2026-08-24, after DeepSeek open-sourced their harness, for "everything's a plug in, and that's Thomas... but I didn't have it actually built correctly." The session log half of that ask shipped the next day; the kernel half was deferred to phase 3.2 and never designed. `thomas/core/kernel/` is that kernel. A context holds services, event subscriptions and child scopes, and every one of those registrations records its own reversal, so unmounting a plugin removes exactly what it added and nothing else — the tool registry it will replace is a dict whose `unregister` is a manual delete with no record of who added what. A plugin declares the services it needs with `inject`; the kernel applies it only once they all exist, withdraws it if one goes away, re-applies it if one returns, and lists the ones still waiting under `kernel.pending()`. That last part is the point: a mechanism whose consumer never arrives is now a fact you can list instead of a no-op nobody notices. It imports nothing else from Thomas, which is what makes it the bottom of the tree rather than another layer alongside.

- **Seams that fail where they are wired.** `thomas/core/kernel/seams.py` names the six capabilities Thomas swaps — tools, llm, sessions, agent_loop, fs, sandbox — as constants rather than strings typed at each site, and `require()` checks a provider structurally so one missing method is reported with the seam and the method named instead of surfacing as an attribute error mid-turn. `seam_report()` says which seams nobody filled and which plugins are still waiting on what.

- **Profiles, so a setup has a name.** `AgentLoop.__init__` takes twenty-three parameters and every surface passes a different subset, which means no configuration has a name and no two can be compared. A profile is an ordered list of named entries, and `extend`, `patch`, `without` and `insert_after` each return a new one, so a host states its variant as a diff against a base instead of a fork of it. Targeting a row that is not there raises rather than quietly doing nothing.

### Changed

- **The agent loop is chosen, not hard-coded.** Nine sites built `AgentLoop(...)` with the constructor typed in directly — the server worker, three CLI paths, plan mode, the forge dispatcher, Telegram, the boot doctor and the benchmark runner — so nothing could substitute a different driver anywhere. They now call `build_agent_loop(...)`, which resolves the `agent_loop` seam and passes every argument through to whatever provides it. The default provider builds the same `AgentLoop` as before, so behaviour is unchanged until something deliberately registers another.

### Fixed

- **Background tasks fired no plugin hooks at all.** The hook dispatcher lived as a closure inside the web chat route, and `worker_runtime` — every background task — passed none, so which lifecycle hooks a plugin saw depended on which surface happened to be running. There is now one dispatcher, `thomas/server/plugin_hook_bridge.py`, imported by both. It sits in the server tier because the architecture permits `server -> plugins` and does not permit `agent -> plugins`, which is what the closure was working around.

- **A plugin's return value was thrown on the floor.** `AgentLoop._run_plugin_hook` said so in as many words — "any return value is ignored" — and the web route called `run_hook(...)` without assigning it. Meanwhile all 528 bundled `pack-*` extensions define `before_tool` and `after_tool` that carefully build a modified payload and return it, against a contract nothing honoured. Hook output is now folded back into the payload and handed to the caller, and the canonical event name feeds its legacy alias so a pack subscribed to either sees what the other did. A failing plugin still cannot break a turn; the payload comes back as far as it got, and the failure logs at warning rather than debug, because a plugin that silently does nothing was the condition worth surfacing.
