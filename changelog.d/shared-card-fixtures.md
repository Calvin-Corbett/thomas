### Changed

- Equivalent fixture Git homes reuse cached patches without Git subprocesses even when their config and template paths differ. Configured external diff-order files bypass both caches so changing their contents changes the observed patch order.
- The four `tests/test_a_shared_card_*.py` modules copy a session-scoped committed Git seed into private per-test repositories instead of rebuilding it. They retain all 167 original assertions and continue to exercise the real promoter.
- Shared-card hand-ins reuse immutable patch bytes keyed by the base commit, requested file contents and repository Git settings. With a loose HEAD, building a new patch takes three Git calls; reusing it in an independent repository takes none. Each hand-in still gets its own metadata and inbox directory. An in-place profile of `test_each_link_is_derived_on_the_one_before` recorded 85 Git subprocesses with the original fixtures and 48 with the shared fixtures; Git time fell from 11.55 seconds to 5.20 seconds, and the two hand-ins took 5.86 seconds and 0.80 seconds respectively.
- The per-test Git read cache accepts only captured, successful reads of pinned objects with allowlisted options. Diffs also require pinned attributes. Mutable refs, replacement refs, grafts, shallow history, external diff/text conversion, redirected output, unknown options and unsupported commands always reach Git.
- Shared-card fixtures explicitly set `THOMAS_CAGE_ROOT` to temporary directories before creating shared repositories or writing submissions. Both submission entry points reject a missing cage or one belonging to another test before reading Git or calling the handoff writer. Regression coverage compares fixture patches with real green hand-offs and checks patch reuse, changed bases, chat metadata, Git settings and independent repositories.
