### Changed
- Build teams keep working while a reload waits for checks to finish. When new server code lands, no new run starts, but the teams already running are now asked to pause only once the checks, hand-ins and the promoter's inbox are done (or after 20 minutes at most). Before this, every team paused the moment the code landed and then sat idle until the checks let the server go. In the 48 hours to 2026-10-25, 8 reloads paused 89 runs, and the teams sat idle for 289 hours before their next run (part of that was two reloads skipped by hand, which left teams paused until they were restarted, and teams parked on purpose). On 2026-10-24 they paused at 09:00 and the server left at 09:33, and one reload held them for 2.5 hours. Once the server leaves it is back in about a minute and the teams carry on within another, so the wait before it leaves was the real cost. You asked for this ("yah ok") after the run records showed it. The step log now records each reload's pause with how long the teams kept working and what held it. The 20 minutes count from the first landing: another change landing during the drain, or git not answering for a moment on a busy PC, does not start them again.
- A team's own test run (`check.run`) now waits at most 2 minutes for room on this PC, down from 10. The wait and the tests share the team's time for one step, so on a PC that stayed busy the tests could run out of time before they began. A test batch of the check before your card now counts the time its wait for room took when it waits for a place in the pool, so it no longer runs past the check's deadline.
- Four tests had been failing since 2026-10-23, when finishing a Thomas project started freezing the change before its second look (da23f510): a conflict test did not bring in a fixture it needs, and three settle tests handed in a stand-in copy that cannot be read. They pass again.
- Two tests of what earlier teams were sent back for had been failing since 2026-10-24 (cdeba624): a fixture they share started blanking that count for every test that uses it. They count again.
- A test of the second look's prompt had been failing since the second look started reading the changed files (2026-10-25, 54ecca1e): it still expected no files. It now expects the files the second look reads.
