### Fixed

- **Every delegated background run had crashed for five days.** `chat_delegation_runner.py:234` passes `tool_receipts=` to `_hidden_completion_review_passes`, and that keyword was added to the call on 2026-09-04 (`11e35e95`, the acceptance-contract work) while the function's signature never accepted it. Each run reaching that line died with `TypeError: unexpected keyword argument 'tool_receipts'`, and the user was told "Background execution failed: TypeError at chat_delegation_runner.py:234" instead of whatever the worker had actually reported. A caller and its callee sat one keyword apart in two committed files, and nothing but a test noticed.

- **The receipts now decide recovery, since that was the point of passing them.** Accepting the argument and ignoring it would have been a mechanism with no consumer — the shape this repository keeps producing. `ToolReceiptLog.unrecovered_failures()` judges each failed tool from the events it observed; the verifier's existing heuristic forgives any failure whenever some other tool succeeded and a file exists, which is coarse. When a receipt log is present it now replaces that heuristic, and the review records which of the two decided, under `recovery_judged_by`. A log that turns out not to be one falls back and says so.

- **Tests were writing into the live checkout, and later tests read it back.** `test_a_done_that_cannot_reprove_itself_goes_back_in_the_queue.py` ran six evidence sweeps with `repo_root=Path(".")`, so anything they wrote landed in `runtime/` and polluted whatever ran next. That is measurable: four test files failed in a batch run and passed when run alone. All six now sweep a `tmp_path` their own test already had, and the meta-test that exists to catch exactly this is green again.
