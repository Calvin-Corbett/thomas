### Fixed

- **An agent you bootstrap in a linked worktree can now claim, ack its mail and commit from that worktree with the exports bootstrap printed.** `bootstrap_claim.py` registered the agent's session in the worktree's own `runtime/`, while the commit tool and the message tool check a session at the coordination root, which is the primary checkout of a linked worktree. So the agent could claim work, but the commit tool refused it with `session_identity` and `message.py` refused its sends and acks. Bootstrap now binds the session at that root. `claim.py --claim` and the takeover checks in `claim_ownership.py` check an actor's binding there too. Without that, the agent could no longer claim again after a release. Worse, a takeover from the worktree rewrote the board and then failed its audit check, leaving a handover with no audit line. Claims stay on the worktree's own board. The holder evidence an automatic takeover reads also still comes from the worktree: folder leases, processes, and the holder's own session record. `tests/test_a_worktree_agent_is_bound_where_it_commits.py` drives the real CLIs in a disposable linked worktree using only the agent's own exports. It covers bootstrap, release, claim again, a dry-run commit stopped by the coordinator's unread P0, the ack, and the same dry run going through. A takeover in the same worktree succeeds and writes exactly one audit row.
