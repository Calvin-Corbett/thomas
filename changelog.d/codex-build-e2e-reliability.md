### Added

- Direct Build can delegate source reviews or isolated single-file work using the selected model and inherited permissions. Helpers stream identified activity; private output is integrated only after ownership, path and original-file checks. The lead remains responsible for combined tests, preview and acceptance.
- Build teams accept up to 100 distinct file assignments with shared request admission, cancellation that joins owned helpers, retained result receipts and interrupted-team recovery. This enables product integration; live 100-agent capacity is not asserted by the offline tests.

### Fixed

- Build acceptance follows the original user request while execution policy stays separate. Child failures retain their actual error and output, and child completion cannot settle the lead response.
- Build check badges use the reported check verdict, including failed checks whose tool invocation itself succeeded.
- Ordinary Chat streaming cancellation releases the owned session handler for the next turn. Server restarts acquire matching application keys for preview and shutdown services.
- Live browser follow-up: Build instructions select checks appropriate to the project language instead of requiring Python parsers for static web files. Chat usage receipts stay with their conversation and disappear from Build and Work.
- Isolated builder instructions explain the engine-run finish declaration and provide a Python syntax-check example, preserving assigned behavioral checks and the lead's integration tests.
- Chat usage readout mounts against the stable shared composer even while navigation still displays another mode's prompt.
- Build disclosure receipts no longer inherit the old icon-column grid; agent names and file summaries remain readable in the activity stream.
- Completion checks resolve a bare data filename to an explicitly named qualified path, avoiding a false extra root-file requirement. Explicit root paths and separately named outputs remain required.
