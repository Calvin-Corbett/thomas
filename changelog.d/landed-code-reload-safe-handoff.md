### Changed
- Landed Python-code reloads now pause new Code run starts while admitted work drains, instead of resetting the reload timer every time a Build is active.
- Active Thomas Build loops yield between completed tool batches when the reload drain is signaled. Verification and acceptance continuation passes preserve that yield as unfinished work instead of retrying it as a failure. The recorder saves it for restart recovery to carry the conversation on after the server reboots.
- Runs that complete during a reload drain leave a pending after-run receipt for restart recovery, without repeating the completed Build; this also carries level-4 Thomas projects to their hand-in check. A repair continuation refused by the drain likewise leaves a pending receipt; restart recovery also resumes reload-yielded Builds below Autopilot. Turning reload off during the drain clears its run-admission gate and signal. While the drain is active, queued Thomas project starts keep their retry count and held hand-in checks do not begin a new check.
