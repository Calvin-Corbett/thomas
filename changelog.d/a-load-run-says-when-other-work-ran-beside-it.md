### Changed

- `scripts/praxis/check_load.py` now records how busy the machine was with other work while each check ran: the share of the CPU used outside the run's own processes, and how many headless browser processes of other work ran (a Build team's playtest, for one). A check is quiet when its readings cover at least 80% of the time it ran and none of them showed other work over a quarter of the CPU or a headless browser process; a check read for less is not measured, never quiet, and the run is quiet only when every check was. Before its usual figures the summary says which. With `--wait-quiet`, its first line says whether the run waited, never got quiet, or did not wait because other load cannot be measured here. Then comes a `quiet:` line when every check was quiet, or an `OTHER LOAD NOT MEASURED` line when no other load was read at all. Otherwise it gives a `NOT QUIET` line, with one line for each check that other work ran beside, when there is such a check, and after them an `OTHER LOAD NOT MEASURED while …` line naming each check that was not read for long enough. So a loaded run is not read as the code's speed. `--wait-quiet SECONDS` (0 for off, otherwise at least 60) first waits for 60 quiet seconds in a row, says so each minute, and starts anyway once SECONDS have passed. On Windows every process the run starts now ends when the run ends, whether it finishes, you stop it with Ctrl+C or it crashes, so an interrupted run leaves no test processes running behind it. A process that asks to break away from the run's job, as `scripts/crew/brief/land_worker.py` does, is not ended with it.
