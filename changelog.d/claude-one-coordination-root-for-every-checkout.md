### Fixed

- **A worker in a linked worktree is now gated on the board the coordinator wrote to.** The message tool and the board lock anchored themselves to the primary checkout through git's shared common directory, while the inbox gate, its Bash hook, the startup router and the commit barrier anchored to whichever worktree held the running script copy. A blocker sent from the primary checkout was delivered to a board those readers never opened: the worktree's startup inbox said zero unread, the hook let Bash run, and a dry-run commit passed its P0 barrier. One resolver, `scripts/crew/workboard/coordination_root.py`, now answers for all of them on their default paths: the coordination root is the primary checkout of the repository whose checkout holds the running script copy, and the tree itself when git cannot answer. Claims stay on the checkout's own board, where `claim.py` and the claim gates keep them. A disposable-checkout scenario (`tests/test_a_worktree_is_gated_on_the_board_the_coordinator_wrote.py`) drives the real CLIs from a primary checkout and a linked worktree: every reader names the same message and board, a dry-run commit from the worktree is refused until the blocker is acked and passes after, the worktree's own board copy is byte-identical afterwards, and the ack leaves the coordinator's decision untouched.
- **A missing board is an error, not an empty inbox.** `list_messages` reported zero messages for a board path that did not exist, so a gate pointed at the wrong path passed. It now fails with the path it could not find.
- **Every printed remediation names the board it was judged on.** The inbox gate, the Bash hook and the startup router print `--workboard` with the absolute, quoted board path, and `commit.py` hands that same board to its inbox gate subprocesses, so the command an agent is told to run reads the board that blocked it.
- **A commit from a linked worktree validates the session binding at the coordination root.** `commit.py` looked for the presence file under the worktree's own `runtime/`, while the message tool looked under the primary checkout's, so one bound session could send and ack but not commit.

### Security

- **The board resolver is integrity-checked.** `coordination_root.py` decides which board the inbox gate, its hook and the commit barrier judge, so it is now in `enforcement_scripts` and hashed in `enforcement_manifest.json` like the gates that read it.
