### Fixed

- **A sleeping machine no longer evicts the waiters of the landing queue who are already polling.** On Windows the monotonic clock counts time asleep, so the first poller to wake read every heartbeat as an hour old and reaped the lot. The queue now notices a poller's own gap and a queue where nobody else has beaten, forgives every heartbeat once, and measures ages and the lease from the wake; a holder's heartbeat also carries the seconds its commit tool has really run. Not covered: after a suspend over 10 minutes, a process that starts polling after the workers have beaten again can still send every other detached ticket to the tail with exit 4 (no work is lost), after about 2 hours an in-flight holder can lose its lease, and a suspend longer than what is left of a ticket's 45-minute limit gives a waiter that is already polling exit 3 (run it again).
- **One stray file can no longer blind the ledger, and a forged heartbeat can no longer get a process killed.** Numbered files are read at any width, a file that is not a valid event is ignored and named by `--verify`, and the reaper kills only the recorded commit tool (start time and command line) after its lease.
- **"Already landed" is exact.** A landing that dev later reverted is landed again, and without `--include` the commit tool's own dry run says what the landing stages, so unrelated dirty files in the shared checkout no longer make a finished landing look unfinished.
- **Smaller fixes.** A job that is set to kill its tree when the worker dies, loud warnings when the OS refuses the job, a bounded pre-check, a once-only "hold overran" notice, a refusal to run two workers on one ticket, a fuller git-lock check (`git -C`, linked worktrees), and plainer briefing text: the 10-minute and 45-minute rules, and what exit codes 1, 2 and 4 really mean. This is a queue, not protection: tamper-evident only, and forging a `by` field evicts a ticket.
