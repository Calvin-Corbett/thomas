### Fixed
- The queued Thomas-project capacity route and starter reuse the project list's cached snapshot instead of independently rescanning every project on each request or selection. Capacity requests and starter ticks remain bounded during a slow refresh, including while a queued start is in flight; only interrupted starts need recovery scans. A snapshot invalidated by a start cannot authorize more starts until its refresh finishes. A queued start checks the capacity ledger before acquiring the queue lock and rejects reservations added after that check.
- Interrupted-start recovery refreshes the project inventory when the cached snapshot and catalog cannot identify a start, and only reconciles reservations whose starting records still match those it checked. If recovery discovers projects absent from the shared snapshot, admission waits for a refreshed snapshot before starting more work. Cancelled local starts can recover their reservations after their tasks exit without waiting for the server process to exit; live peer-server reservations remain reserved.
- Capacity admission counts active projects in the shared snapshot even when another server owns them, without counting a locally tracked project twice. Capacity status includes locally tracked projects absent from that snapshot.
- Incomplete or superseded snapshots cannot authorize starts, including when refresh failure flags are stored alongside preserved complete cards. Recovery reads the capture time before the project rows and rechecks snapshot validity before giving up an interrupted start after its grace period. Malformed conversation records mark strict inventory reads incomplete instead of silently undercounting projects.
- Cache and nonblocking queue regressions exercise the real routes and durable queue without booting unrelated server services or creating a source checkout. Shared queue fixtures import the project request and settings from their defining module. Selection-dependent queue tests await cache readiness before asserting admission. Regression coverage checks shared TTL reuse with 20 and 200 projects and recovery after scan exceptions with both cold and warm caches. Project-start and hand-in tests use temporary persistence. The chat project-list request-body mock supports aiohttp's read-chunk-size hook.
