### Changed

- **The window's checker does not take a test report on trust from the account whose change it is checking.** A change's tests run as `thomas-runner`, which writes the JUnit report the checker reads, so the checker now guards that report: it reads it only after the test process and everything it started are dead, it refuses a report whose process was killed or crashed rather than finishing as a test run, and it refuses a report that carries cases for files the checker did not select -- either one is answered FAILED, never a pass. `thomas-runner` still has no write on the jobs, results or state folders, so it cannot write the answer the promoter reads or another job's. A change that rewrites its own report with a matching set of passing cases and a clean exit remains something only the second look stands against; the elevated step that would close even that (handing pytest a report handle the runner cannot reopen) is written up in `OWNER_STEPS.md`.
