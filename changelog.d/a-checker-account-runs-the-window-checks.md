### Added

- **A checker of its own runs the tests a window relies on.** A new Windows account, `thomas-checker`, made by your one elevated setup step (`scripts/cage/enable_window.ps1`), runs the tests that cover a change in copies made from the commit the promoter derived, never from a team's copy. Each failure is run again alone with the change and alone without it, and the checker also makes sure Thomas still starts. A failure no re-run can settle is answered as "could not check" and tried again, never sent back to the team as a failure. Its answer goes into a folder only it can write, which the Build teams' account cannot even read; it reaches nothing beyond this machine; and the promoter takes an answer only for the exact job it posted (its base, commit and tree). A change's own tests run as a separate account (`thomas-runner`) that cannot write the answer, so a change cannot write its own "passed" or another job's; the window's second look still stands behind that.
