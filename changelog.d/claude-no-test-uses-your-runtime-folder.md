### Fixed

- **No test run uses your runtime folder any more.** A shell that runs Thomas carries `THOMAS_MEMORY_ROOT` pointing at your checkout's `runtime` folder, and the test guard neither moved it nor watched that folder: it was not one of the data folders the guard knew. On 2026-09-25 a server booted for a check from such a shell wrote `serve.lock` and three empty SQLite side files into your real `runtime\.thomas` before it was stopped; no database rows changed. The test run now points `THOMAS_MEMORY_ROOT` at a folder of its own, like `THOMAS_DATA_DIR`, before anything imports Thomas. `test_load_config_defaults_profile_runtime_env_and_production_overrides` clears it the way it already clears `THOMAS_HOME` and `THOMAS_RUNTIME_DIR`: on your machine it had been failing because of the inherited value.
