### Fixed
- **Two Code conversations bound at the same moment both keep their project.** Binding a conversation to a project was read the registry, add the row, write the registry, with nothing between the read and the write; two binds at once (Thomas runs Code tasks in parallel, so this is the ordinary case) each read the same file, each added their own row, and the second write erased the first's. A conversation with no row has lost its project: every later read falls back to the catalog root and comes back empty. Measured with two threads binding 150 conversations each, 153 of the 300 rows were gone. Every writer of the registry -- bind, a settings change, forget, and the rename of a task folder on its first message -- now runs its read and write under one lock, this process's and a file beside the registry that another server's process also takes, the same shape as the Autopilot park list. The temp-file and read-as-empty halves of this were fixed earlier; this is the lock.
