### Added

- **Your window: one Windows sign-in lands Thomas's checked changes without a card for each.** You ask for a window with `scripts/cage/window_control.py open`, and only your sign-in on the pinned card opens it. While it is open, every waiting change that no card has taken lands by itself, with no card and no one else asked first, when all of these hold for exactly what would land: the checker passed it on the dev it lands on, with its tests run as `thomas-runner` and the answer written by `thomas-checker`; a second look, run from a fresh copy with no project settings or instruction files loaded, found it safe; every check a card landing runs passed; and no file of it is on the never-in-a-window list (the cage, gates, scripts, docs and plans, notes agents read, files that run as you, every config file pytest reads in any spelling, deletions, and every file a process of yours loads). A change with a file on that list keeps its own card, and when the window ends every change it had not landed goes back to its card, exactly as before. The window lasts as long as you chose, at most 120 minutes; lands at most 25 changes; pauses while your PC is locked; and ends after 15 minutes locked or idle, on a sign-out or restart, when the promoter restarts, or with an off switch (`window_control.py off`, or `window.off` in the pin folder). After each landing nothing else lands until the checker has run the window's tests on the new dev; a failure closes the window and asks you, on its own card, to undo that change. Any change can be undone on its own card once the checker has passed the undo. Each landing names your window in its commit and never claims a card, and the window's record is kept where you can add to it but never change it.
