### Added

- **`-Stop` and `-Restart`, with exit codes that say what happened, and a Thomas that moved to another port is found.** When the default port (8899) is busy, Thomas starts on the next free port. A launch where you did not name a `-Port` records the port it starts on in `runtime\thomas.port`, and a later launch that finds no Thomas on 8899 looks there too: it opens the Thomas that is there (or replaces it, with `-Restart`) instead of starting another. It acts there only on a Thomas that is this copy: a Thomas from another copy on the recorded port, or a program there that does not answer as Thomas, is left alone by a launch and by `-Stop`. A `-Port` you name is the port: the recorded one is not read and not written, so `-Port 8901` acts on 8901 only and never on a Thomas running on another port. `-Stop` looks on that one port when you name one, and otherwise on 8899 and the recorded port (when it holds this copy's Thomas), and then checks them: it exits 0 when it ended a Thomas, 5 when it found none, 6 when a Thomas is still there afterwards, and 3 while a Build run is active. The `-Restart` command a launch prints, and the stop command printed for a direct launch, carry `-Port` for the Thomas they are about, so they never act on a different one. `launch-thomas.vbs /stop` turns those into messages: Thomas is stopped, no Thomas was found to stop (the launch log says which ports were checked), or Thomas could not be stopped. A program on the port that is not Thomas is not stopped, and it does not count as a failure to stop.

### Fixed

- **Opening Thomas again no longer ends a Thomas that is in the middle of a Build.** `run-ui.ps1` ended any Thomas server on the port before starting its own, so a second double-click, or one `thomas://` link, could cut a Build off. It now asks the server on the port who it is: `/api/health` names its folder, version, commit and how long it has been up. The copy you launched is reused, the browser opens at it, and the launch prints which build that is (the commands it suggests carry this copy's full path, so they work from whatever folder you open the launch log from). A server that is another copy (a different folder, version or commit), that was started from a working tree with uncommitted changes, or that started before a `.py` under `thomas\` or your `thomas.toml` was last written, is replaced, so running the launcher again still picks up your edits. If it is running a Build it is left running and opens instead; the launch says so, and the Start Menu shortcut shows a message with the command that replaces it. A Thomas that is this copy and current but reports `degraded` on `/api/health` is reused too, because replacing it would end a chat in flight, and the launch says so: the log marks it `(reporting degraded)`. When `/api/health` names a cause a restart or repair can change (a startup check that failed, or no cause at all), the launch exits 7 and the Start Menu shortcut shows a message that it reports degraded, with the `/restart` command to use after a repair. When the only cause it names is `model_auth` (no model sign-in is stored yet, which a restart cannot change and the app shows in chat), the launch exits 0 and shows no message. The launcher asks again just before it stops the old server, because installing and first-run setup can take minutes and a Build may have started since; a Build that starts between that last check and the stop is still ended. A Thomas that answers but does not say whether a Build is running (an error, a refusal, or an answer without that field) is left running when it is not this copy or is out of date, so after an upgrade an older server can still be the one that opens; the message says so. A Thomas that answers 404 on the Build status route has no Build run to cut off, so when it is another copy or out of date it is replaced like any idle one. A listener whose command line looks like a Thomas server and that does not answer `/api/health` within ten seconds is stopped and replaced even if it is busy with a Build, which ends that Build: the launcher cannot tell a busy server from a stuck one, and the launch says what replacing it costs. A program on the port that does not look like a Thomas server is left alone, and Thomas starts on the next free port. New switches: `-Restart` replaces the running one on purpose and is refused while a Build run is active; `-Stop` stops the server, which now runs without a window. `run-ui.cmd` now hands its arguments to the launcher, so `run-ui.cmd -Restart` and `run-ui.cmd -Stop` work, and so does the `run-ui.cmd -NoTray -Port 8899` that the boot doctor tells you to run, which was ignored.
- **A second double-click while the first launch is still starting no longer takes over the port, and a launch that fails no longer fails silently.** The Start Menu shortcut runs hidden. A second click while the first launch was still installing or starting ended the first launch's server, and a launch that failed showed nothing at all. Each launch now writes `runtime\logs\launch-<date>-<time>-<n>.log` (the newest five are kept, and one still open in a running launch stays until it closes), a failed launch shows a message with the exit code and the path of that log, and a launch waits up to ten minutes for one that is still in progress, then finds Thomas running and uses it.
- **Starting Thomas no longer rewrites your `thomas://` handler every time.** The launcher wrote it into your Windows account on every launch, pointing it at whichever copy of Thomas ran last, and said nothing. It is now written only when none exists or the copy it names is gone, and the launcher says so and how to remove it. `-NoProtocolHandler` skips it; `-RegisterProtocol` points it at this copy on purpose.
- **First launch no longer installs Node.js, the Codex CLI and Ollama on its own.** Setup ran with `-AutoInstallTools`, so winget and npm installed all three without a prompt, in a hidden window when started from the Start Menu shortcut, and the default profile needed none of them. They now install only with `-InstallTools` or `THOMAS_AUTO_INSTALL_TOOLS=1` on a first launch (afterwards, `setup.cmd` installs them), and the launcher says what setup is about to do. Without Node.js the desktop shell is not installed, so web tabs stay blank on sites that refuse framing; when Node.js is already there, first-run setup still runs `npm install` for the desktop shell.
- **The Microsoft Store `python.exe` stub is no longer taken for Python, and a newer Python is.** On a machine with no Python the stub comes first on PATH, so the launcher never reached its automatic install and failed creating the environment, in a hidden window. A Python is now used only after it runs and reports the version `requires-python` in `pyproject.toml` asks for (3.10 or newer, no upper bound; a test reads that file and fails if the probe, the `py` flags, the winget installs or the messages name another version). The `py` launcher is asked for 3.13 down to 3.10 before the newest, with `PYTHON_MANAGER_AUTOMATIC_INSTALL=0` set for the probe only, so it does not install a runtime it lacks; `PYTHON_MANAGER_CONFIRM` is left as it was. A system Python is looked for only when `.venv` has to be created, and only when none runs does the launcher install one with winget, saying so first. `run-repl.ps1` gets the same check. The failure message names the log and asks for Python 3.10 or newer.
- **The Start Menu shortcut no longer leaves a terminal window open, and says how to stop Thomas.** The server was started without a window style, so Windows Terminal showed a window titled with the path of `python.exe` for as long as Thomas ran, and closing it stopped Thomas. The server now starts hidden; its output is in `runtime\logs`. Because there is no window to close, the first launch through the Start Menu shortcut (`launch-thomas.vbs`) that works shows a message, once, saying that Thomas keeps running after you close the browser and giving the command that stops it: `wscript "<folder>\launch-thomas.vbs" /stop`. The message is shown only when `runtime\` can be written to, because `runtime\background-notice-shown` is how it is remembered; a launch through `run-ui.cmd` or a `thomas://` link shows none, and the terminal line for a direct launch says how to stop it. The shortcut's dialogs ask Windows to put them in the foreground, because a box opened by a background script can otherwise open behind other windows. `launch-thomas.vbs /stop` stops it and `launch-thomas.vbs /restart` replaces it, for a shortcut to pass; they act on port 8899 and on the port recorded in `runtime\thomas.port` when the Thomas there is this copy. `run-ui.cmd -Stop` does the same from a terminal; with a `-Port` it acts on that port only.
- **`run-repl.cmd` now starts Ollama for a local profile and warns about a missing API key.** The patterns that read `thomas.toml` had doubled backslashes, so `\\s` matched a literal backslash and the default model came back empty. They now match what `run-ui.ps1` matches.
