### Added

- **A plugin turned on while Thomas runs now gets almost everything a feature gets at startup.** Most of Thomas's features could not become plugins yet, because the part of the app a plugin sees could only read. A plugin can now store things on a server that is already running, add its routes in the other ways features do, serve a folder of files, and have startup and cleanup steps run in the order the web server itself uses. Whatever it stored goes when it goes. An open stream, such as a page watching live events, no longer has to hold the off switch: a plugin can name its streams and they end when you press off. A plugin whose running work calls back in through its own routes can keep them until that work is over. Turning a plugin on no longer freezes the server while its code loads, as long as the plugin names what it loads. Two plugins claiming one route now fail alone instead of stopping Thomas starting. A plugin that fails while you turn it on takes its background work with it and leaves the plugins already running alone. Nothing you can see changes yet: this is the base for moving more of Thomas into plugins.
