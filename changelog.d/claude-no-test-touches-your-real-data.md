### Fixed

- **No test run writes your real Thomas data any more.** `load_config()` copies the data-folder paths (`THOMAS_DB_PATH`, `THOMAS_RUNS_DB_PATH`, `THOMAS_TASK_LEDGER_DB_PATH` and about twenty more) into the process environment, and in a test run they outlived the test that called it. On 2026-09-24 that let `test_build_role_models` write `build_builder = gpt-5.6-terra` into your real preferences database, and every agent's test sweep that day did the same. In a sample of 54 test files, 106 tests reached your real data folder: the preferences and task-ledger databases, `machine_capacity.json`, `thomas_state.json` and `shared/secrets.json`. Before anything imports Thomas, the test run now points `THOMAS_DATA_DIR`, `THOMAS_HOME`, `THOMAS_STATE_DIR` and the shared secret store at a folder of its own, and drops any inherited data path that leads into your real folder. Every test gets the `THOMAS_*` environment back exactly as it found it. If your real `thomas.db`, `.thomas/*.sqlite3` or `json/*` files change while the tests run, the run fails and names each file. The one exception is a self-fix green, where that folder is the caged Thomas's own: there the files are named and the result stands. Your Build builder model setting was not restored, because its earlier value is unknown; you can set it again in Build's settings.
