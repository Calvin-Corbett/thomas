### Removed

- **The 528 generated extension packs are gone, and the marketplace stops advertising what it cannot install.** Measured before deleting: 528 directories of three files each, with exactly **two** distinct `hooks.py` shapes once identifiers were normalised — one template stamped 480 times, another 48 times. Nothing ever loaded their code; `extension_catalog_runtime` checks that `hooks.py` exists and never imports it. None of them was installable either — the real validator answers *"Plugin 'pack-alerts-email' is not installable as a desktop plugin."* And yet `classify_marketplace_row` returned `availability: installable`, `promotion_status: official_hosted` for them, byte-identical to the verdict on the genuine `paper-trading` extension. The storefront offered 480 entries that failed the instant anyone chose one. Forty-eight of the 528 were not even in the catalog, indexed by nothing and reachable by nothing. The five real extensions — `desktop-operator`, `inkwell`, `life-manager`, `life-manager-foundation`, `paper-trading` — are untouched, and a test now names them so a later cleanup cannot sweep them up.

- **The generator that made them, and the test it wrote to prove they existed.** `scripts/generate_gap_assets.py` produced the packs, the catalog rows, and `tests/test_extension_pack_catalog.py` asserting at least 480 packs were present. A generator that writes both the artefacts and their evidence can only ever pass. `generate_extension_packs()` is removed along with the block that wrote that test, so a single run cannot bring the packs back; its browser-workflow generators are untouched. A test now asserts no `pack-*` directory may reappear, because a deletion a merge can undo is not a deletion.

### Fixed

- **Certification was passing on padding.** Extension certification requires a `healthcheck` capability at a 95% pass rate. Every one of the 480 packs *declared* `healthcheck` while its `hooks.py` defined nothing but `before_tool` and `after_tool`, which lifted the rate over the bar without implementing the thing being certified. Measured on the five real extensions the rate is 1 in 5 — only `paper-trading` both declares it and defines `def healthcheck()`. The shape test no longer asserts a threshold it can only meet by re-adding filler; it asserts the payload shape and that no catalog row is invalid. Whether the other four extensions should implement a healthcheck is a decision, not a regression to paper over.

### Added

- **A test that the marketplace and the installer agree.** Every catalog row that `classify_marketplace_row` marks `installable` must survive `load_bundled_desktop_plugin_manifest`, the validator the install path actually runs. Those two disagreed for 480 rows and nothing noticed, because no test ever asked them the same question.
