### Added
- Every step Thomas takes is timed into one log, so there is data to pull from when you decide what to improve. You asked on 2026-10-25 ("very single thing should be measured and tracked so we hacve data to pull from when we decied what to improve") when the speed board could only say where 22% of a week's time went. Each model call (seconds, the model that answered, prompt and reply tokens), each tool call, each Build run from your request to its end (and how it ended, such as finished or yielded to a reload), each project start (copy, bind and first run apart), each check before your card, each second look, each wait for room on this PC, and each reload (when the drain started and how long it held runs) now writes one line with the PC's CPU and memory at that moment. The lines are kept a file per day under Thomas's data folder in `metrics`, for 90 days, so the record stays small. `/api/metrics/steps?days=N` sums them up: totals and slowest cases per kind of step, runs by how they ended, tokens per model, the 15 slowest tools, where the waits for room happened, and how often the PC was at or over 90% while work ran. `THOMAS_STEP_LOG=off` turns it off.
