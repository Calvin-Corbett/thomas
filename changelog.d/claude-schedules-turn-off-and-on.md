### Changed

- **Scheduled tasks can now be turned off and on while Thomas runs.** The six `/api/schedules` routes and the thread that starts your tasks moved out of the server's fixed list into a row called Scheduled tasks, which ships on, so nothing changes until you turn it off. While it is off no task starts at its time, those routes answer 404, and Scheduled tasks in Settings says it could not load them once you reload it. A task already under way is not stopped: neither off nor Stop now waits for it or ends it, and it can take up to half an hour. A task already waiting to start still starts and can take as long, so the last of them can end more than half an hour after you turn this off. Your list stays saved, and `thomas cron` can still read and change it: a run that ends after off adds only its own record to the file, so it can no longer put back an old copy of your list. Back on, each task that came due runs straight away: most run once, and one that comes due every few minutes can run several times in a row after a long time off. The thread now starts only once the row has been accepted, so a row refused for its routes leaves nothing running. `/api/health` no longer counts schedules, so if the row fails the Plugins page is where you see why. The Mission queue is a separate list and is not affected.
