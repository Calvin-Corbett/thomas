### Changed

- **More of what Thomas sends a ChatGPT model is served from its cache, so Build runs wait less and spend less.** The step log's new request rows showed where caching was lost: even a request that only grew at the end of the one before it was served 37% from cache, because the session header the backend keeps one session's calls together by was never sent, only the key in the body; and 41% of requests rewrote an earlier tool output, because once a run passed a third of its window the oldest unshortened output was cut on every call, each cut a break in the cache. Each request now carries its run's key as its session, and old tool outputs are cut six or more at a time (all at once past half the window), so the cache breaks once per batch rather than on every call.
