### Fixed

- **A Thomas project can no longer stop another project's processes.** Every Thomas project's commands, the caged server and the caged shell run as one account. One team, cleaning up after its own checks, listed every python process whose command line held "pytest" or "thomas" and force-killed the list, which could end other projects' test runs or Thomas itself; the one process it could not stop belonged to another account. The caged shell already keeps each project's processes in a job of their own. Now a command from a project's copy that stops processes (taskkill, Stop-Process and its aliases, wmic, CIM Terminate) must name every target by id, and each id must be a process that project started. A stop by name, by filter or through a pipe is refused, and the refusal lists the project's own processes with their command lines. Every team is also told this in its lessons. A program that stops a process itself is not covered.
